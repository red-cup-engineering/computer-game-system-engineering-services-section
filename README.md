## From game requirements to executable designs

The current idle-game path keeps each title's requirements, design contract and
receiving evidence with its original source owner. The shared
[JSNode module producer](https://github.com/red-cup-engineering/jsnode-package-engineering-services-section/blob/54d3f339bd587bc29832c3446762d9e4856495a7/README.md)
owns schema admission and deterministic data-to-ESM projection.

### Repeatable fabrication procedure

1. State the change as requirements and examples beside the title's design.
   Identify the original values, persistent IDs, save interpretation and game
   rules that must survive. A schema constrains representation; the existing
   game remains responsible for its semantic relationships.
2. Derive independent acceptance and refusal cases from those requirements,
   original data and actual consumer behavior. Keep their authorship separate
   from the producer or adapter implementation. Use failed cases to correct
   their actual owner, retaining the original failure and its cause.
3. Select the immutable shared producer and retain a native package-manager
   lock. Pass the literal design through `projectJsnodeModules({dataModules,
   operations: []})`. A title adapter owns its fixed paths, complete admission
   and filesystem replacement; the shared supplier owns JavaScript emission.
4. Generate the frozen module, then make the existing runtime consume it.
   Reject malformed UTF-8, parse and validate the JSON, retain raw-input
   digests, compare complete generated bytes, and preserve unchanged output.
   Reject invalid input before replacing an artifact.
5. Put the read-only freshness gate at the start of the actual build.
   Exercise an admitted design edit through real game transitions and the built
   browser module graph. A generator unit test alone cannot establish that a
   player-facing artifact received the design.
6. Run the original native suite and independent cases against the selected
   suppliers. Require successful process execution and complete test results;
   report explicit skips and missing environmental requirements. Retain the
   immutable dependency selection and native lock alongside the existing build
   or release receipt, so the design, schema, producer and artifact identities
   can be traced together.
7. Advance the existing source-owner gitlinks after receiving the exact child
   revision. Record source integration, installed dependencies, built release,
   serving activation and player receipt as distinct observed outcomes.

For Little Worlds, `node scripts/generate-worlds.mjs` materializes a changed
catalog and `--check` verifies it without writing. For You Are Conscious,
`node scripts/generate-conscious-design.mjs` provides the equivalent boundary.
Both actual static-build entrypoints perform their own freshness gate.

This path currently fabricates schema-admitted data and content into executable
modules. New algorithms still require their own requirements, implementation
and behavioral receiving. A new schema does not migrate saved runs, and a
passing build does not establish a public deployment or human playthrough.
