# Capability Development

FizzOS capability work is theory-first.
Before implementing a new game or engine capability, inspect the archive and current `lib/` packages for relevant theory and prior experiments.

Minimum starting surfaces:

- Computing and operating-system theory in the archive and current MEMETICS packages.
- Concurrent game-system, MUD, tab, Farstone, and Bussard material in the archive.
- Ludics, play, uncertainty, emergence, virtual economy, and colony/vehicle-system notes.
- Current `web-*`, `memetics-*`, `spacetime`, SWARM, and language packages that can supply the capability as substrate rather than decoration.

The implementation standard is not "add a feature because it feels right."
Derive mechanics from local theory, identify the memetic/paraconsistent invariant they preserve, then implement the smallest package surface that makes that invariant executable and testable.
